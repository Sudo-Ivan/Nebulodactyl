NEBULODACTYL

A self-hosted panel for running game servers. Based on Hydrodactyl and Pterodactyl, with optional Nebula overlay networking for nodes that sit behind NAT or on private networks.

View on GitHub Install guide

Features

Everything Hydrodactyl ships, plus the additions below.

Nebula overlay

Panel-to-node traffic can run over a mutually authenticated Nebula mesh. Nodes enroll themselves and get a signed certificate and an overlay IP from the panel.

nebulod agent

A small Go service that runs on each node. It enrolls with the panel, writes the Nebula config, keeps the tunnel up, and exposes a local status endpoint.

Dark interface

Monochrome dark theme with a subtle starfield. Readable at night, no color noise.

Full client panel

Console, file manager, databases, backups, networking, subusers, startup config, schedules, and activity logs in one place.

Plugin marketplace

Install plugins and mods for Minecraft servers directly from Modrinth, Hangar, and Spiget.

Reverse proxy ready

Runs behind Coolify, Traefik, nginx, or Caddy. Trusted proxy handling and a /healthz endpoint are built in.

Database options

MySQL, MariaDB, or PostgreSQL for production. SQLite for small or single-user installs.

Signed builds

Container images and release tarballs ship with Cosign keyless signatures, SBOMs, and provenance attestations you can verify.

Networking

The panel works on a public domain behind a reverse proxy, or entirely inside a private network. Panel-to-node traffic does not need to cross the public internet.

Public deployment

Point a domain at the panel, put your proxy in front, set TRUSTED_PROXIES, and terminate TLS wherever you like. This is the standard setup.

Private network or VPN

Nodes on a LAN, WireGuard, or Tailscale work fine. Give each node its private address or internal hostname and the panel talks to it directly.

Nebula overlay

For fleets spread across sites or NATs, enable the built-in Nebula support. The panel runs a CA, nodes enroll with their daemon token, and daemon traffic moves to overlay IPs automatically.

PortPurpose
80/443 TCPPanel web interface, behind your reverse proxy
8080 TCPNode daemon API (game server control, WebSocket console)
2022 TCPNode SFTP file access
4242 UDPNebula overlay traffic, when enabled
9770 TCPnebulod agent status endpoint, overlay only
Overlay setup: run php artisan nebula:init-ca on the panel, then run nebulod on each node. Nodes enroll with their existing daemon token and the panel prefers the overlay IP for daemon traffic. See config/nebula.php and agent/README.md.

Install

Docker, one command

Requires Docker and the Compose plugin. The script asks a few questions, generates secrets, and starts the stack.

curl -fsSL https://raw.githubusercontent.com/Sudo-Ivan/Nebulodactyl/master/install.sh | bash

Manual compose

If you prefer to review everything first:

git clone https://github.com/Sudo-Ivan/Nebulodactyl.git
cd Nebulodactyl
cp docker-compose.example.yml docker-compose.yml
cp .env.example .env
docker compose up -d

After it is up

On first boot the panel prints a setup link to its logs (docker compose logs panel). Open it to create the admin account in the browser. The link is only valid while no users exist and expires after one hour. If it lapses, mint a new one: 

docker compose exec panel php artisan p:setup:link

Then add a location and a node in the admin area.

This is pre-release software under active development. The upstream Hydrodactyl documentation covers game server setup, wings configuration, and egg management. See examples/coolify/ for a ready-made reverse proxy deployment.
